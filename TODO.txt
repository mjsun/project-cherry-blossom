1. Data prep:
Split the document into lines(or short blocks)
Label each one:
    1 = chunk boundary
    0 = not a boundary

eg.
    "RISK FACTORS"                          → 1
    "You should carefully consider..."      → 0
    "Retail Properties Have Special Risks"  → 1
    "Retail properties are subject to..."   → 0

Approach: LLM for initial labeling + manual fine tune

Extract the document into lines/blocks
Send batches of lines to an LLM with a prompt like: "For each line, label 1 if it starts a new section/subsection/loan, else 0"
Save the LLM's labels (line → 0/1)
You review a sample, fix mistakes (the "manual fine-tune" of the labels)
That corrected set = your training data


Options of LLM for labeling
For a free local LLM to auto-label, good options (run via Ollama — easiest local runner):
Best balance (need ~8–16 GB RAM):
Llama 3.1 8B — strong general model, good at following labeling instructions
Qwen 2.5 7B — excellent at structured/instruction tasks, often better than Llama for this
Lighter (4–8 GB RAM):
Llama 3.2 3B — smaller, faster, still decent
Phi-3 mini (3.8B) — tiny, surprisingly capable
Local DeepSeek options:
DeepSeek-R1 distilled (7B / 8B) — reasoning-focused; good at "think through which lines are boundaries." Available as deepseek-r1:7b / :8b in Ollama.
DeepSeek-V2/V3 — the full models are too big for local (hundreds of GB). Stick to the distilled 7B/8B for your machine.
